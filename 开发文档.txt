相比之前文档里的完整售后系统，这一版会刻意减少业务表、角色、状态和 Agent 数量，优先保证 Codex 能快速生成并跑通。

# ContentFlow 一站式内容策划与生成平台

## 1. 项目介绍

ContentFlow 是一个面向个人创作者的 AI 内容策划与生成平台。

用户创建一个内容项目，填写账号定位和目标受众，然后在对话框中输入创作要求，例如：

> 帮我写一篇面向 Java 初学者的小红书文章，主题是 Spring Boot 登录认证。

系统通过 LangGraph Agent 分析用户需求，使用 RAG 检索项目素材，并通过 ReAct Agent 调用选题查询、知识检索和内容保存工具，最终生成结构化文章。

项目重点不是复杂内容运营，而是实现以下完整闭环：

```text
创建项目
→ 上传参考资料
→ 输入创作要求
→ Agent理解需求
→ RAG检索资料
→ 生成内容
→ 用户修改
→ 保存文章
```

## 5. LangGraph 工作流

第一版只建立一个主 Graph。

```text
START
  ↓
parse_request
  ↓
need_retrieval？
  ├─ 是 → retrieve_knowledge
  └─ 否
        ↓
    generate_content
        ↓
    format_output
        ↓
    END
```

### 节点说明

#### parse_request

提取：

* 内容平台
* 内容类型
* 主题
* 目标受众
* 内容风格
* 字数要求
* 是否需要使用知识库

#### retrieve_knowledge

根据用户问题在当前项目知识库中执行向量检索。

默认返回最相关的 5 个片段。

#### generate_content

根据以下上下文生成内容：

* 用户创作要求
* 项目定位
* 目标受众
* 内容风格
* RAG 检索结果

#### format_output

使用 Pydantic 将模型输出转换为固定结构：

```json
{
  "title": "Spring Boot JWT登录，看这一篇就够了",
  "summary": "介绍JWT登录的基本流程和关键实现。",
  "content": "正文内容",
  "tags": ["Java", "SpringBoot", "JWT"],
  "references": [
    {
      "documentId": 1,
      "fileName": "SpringBoot学习笔记.md",
      "chunkIndex": 3
    }
  ]
}
```

## 6. ReAct Agent 设计

为了体现 ReAct，不需要开发多个 Agent。

只创建一个 `ContentAgent`，绑定三个工具。

### 工具一：get_project_context

根据 `projectId` 获取：

* 项目定位
* 内容平台
* 目标受众
* 内容风格

### 工具二：search_knowledge

参数：

```json
{
  "projectId": 1,
  "query": "Spring Boot JWT登录",
  "topK": 5
}
```

返回当前项目的相关知识片段。

### 工具三：save_content_draft

Agent 生成内容后，可以调用 Java 接口保存草稿。

为了避免 Agent 任意写数据，保存工具必须携带当前用户 ID，并由 Spring Boot 校验项目归属。

ReAct 执行示例：

```text
用户要求根据项目资料写文章
    ↓
Thought：需要先获取项目定位
    ↓
Action：get_project_context
    ↓
Observation：项目面向Java初学者，风格通俗
    ↓
Thought：还需要查找JWT相关资料
    ↓
Action：search_knowledge
    ↓
Observation：返回5个相关片段
    ↓
Thought：资料已经充分，可以生成文章
    ↓
生成结构化内容
```

1. 创建 ContentAgent。
2. 添加项目上下文工具。
3. 添加知识检索工具。

1. Spring Boot 调用 LangGraph 服务。
2. Vue 调用 Spring Boot。
3. 使用 SSE 显示生成内容。
4. 保存 Agent 生成结果。

## 15. 给 Codex 的执行要求

请按照以下规则开发：

1. 优先保证项目能够启动和完整联调。
2. 后端采用单体 Spring Boot，不拆微服务。
3. 每个接口提供参数校验和统一异常处理。
4. 数据库脚本放在 `sql/init.sql`。
5. 提供 `.env.example` 和启动说明。
6. Vue 页面保持简洁，不开发复杂动画。
7. Agent 输出必须使用 Pydantic 结构化模型。
8. 所有 RAG 检索必须使用 `projectId` 过滤。
9. Agent 不直接操作 MySQL，只能调用 Spring Boot 内部接口。
10. 每完成一个阶段后更新 README。
11. 使用模拟数据保证首次启动后可直接演示。
12. 最终提供 Docker Compose，启动 MySQL、Redis、MinIO、Chroma、Java 后端和 Agent 服务。

这个版本的工作量比较合理，核心亮点也足够明确：**一个 LangGraph 工作流、一个 ReAct Agent、三个 Tool、一套项目级 RAG、六个前端页面、八张核心业务表**。
