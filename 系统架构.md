下面这套架构适合你当前的 **ContentFlow 入门级 MVP**，重点是保持单体、边界清晰、方便 Codex 分阶段生成。

# ContentFlow 系统架构与项目目录设计

## 1. 整体系统架构

ContentFlow 采用前后端分离架构，由四个核心服务组成：

```text
┌─────────────────────────────────────────────┐
│                  用户浏览器                  │
│                                             │
│          Vue 3 + TypeScript 前端             │
└──────────────────────┬──────────────────────┘
                       │ HTTP / SSE
                       ▼
┌─────────────────────────────────────────────┐
│              Spring Boot 业务后端            │
│                                             │
│  用户认证、项目管理、文件管理、内容管理、会话管理 │
│                                             │
│  Spring Security + JWT                      │
│  MyBatis-Plus + PostgreSQL                  │
└───────────────┬───────────────┬─────────────┘
                │               │
                │ HTTP          │ 文件存储
                ▼               ▼
┌──────────────────────┐  ┌──────────────────┐
│ LangGraph Agent 服务  │  │      MinIO       │
│                      │  │                  │
│ 需求解析             │  │ PDF、TXT、MD文件 │
│ ReAct 工具调用       │  └──────────────────┘
│ RAG 检索             │
│ 内容生成             │
│ 结构化输出           │
└───────────┬──────────┘
            │
            ▼
┌──────────────────────┐
│       Chroma         │
│                      │
│ 文档切片             │
│ Embedding 向量       │
│ 项目级语义检索       │
└──────────────────────┘
```

基础设施：

```text
PostgreSQL：业务数据
Chroma：向量和知识片段
MinIO：原始文件
Redis：缓存、登录辅助信息、SSE临时状态
```

---

## 2. 各模块职责

### 2.1 Vue 前端

前端只调用 Spring Boot，不直接调用 LangGraph、Chroma 或 MinIO。

主要职责：

* 登录和注册
* 项目管理
* 素材上传
* AI 创作对话
* SSE 流式内容展示
* Markdown 编辑
* 内容保存和查看

前端访问链路：

```text
Vue
  ↓
Spring Boot
  ↓
LangGraph / PostgreSQL / MinIO
```

---

### 2.2 Spring Boot 后端

Spring Boot 是整个系统的业务入口和权限中心。

负责：

* 用户认证和 JWT 校验
* 用户、项目、文档、内容 CRUD
* 校验项目是否属于当前用户
* 上传文件到 MinIO
* 保存 PostgreSQL 业务数据
* 创建 Agent 会话
* 调用 LangGraph 服务
* 将 Agent 流式结果通过 SSE 转发给前端
* 向 Agent 提供受保护的内部接口

Spring Boot 不负责：

* 文档向量化
* Chroma 检索
* 大模型内容生成
* ReAct 推理

---

### 2.3 LangGraph Agent 服务

Agent 服务是独立 Python 工程。

负责：

* 解析用户创作要求
* 获取项目上下文
* 判断是否需要知识检索
* 从 Chroma 检索项目资料
* 调用大模型生成内容
* 使用 Pydantic 输出固定结构
* 通过 ReAct 调用工具
* 将生成过程流式返回 Spring Boot

Agent 不直接操作 PostgreSQL。

需要读取或保存业务数据时，只能调用 Spring Boot 内部接口。

---

### 2.4 PostgreSQL

PostgreSQL 保存业务数据：

```text
sys_user
cf_project
cf_document
cf_document_chunk
cf_content
cf_content_tag
cf_agent_conversation
cf_agent_message
```

PostgreSQL 不保存 Embedding 向量。

`cf_document_chunk` 只保存：

* 文档 ID
* 项目 ID
* 切片序号
* 原始文本
* Chroma 记录 ID
* Token 数量

---

### 2.5 Chroma

Chroma 保存：

* 文档切片内容
* Embedding 向量
* 文档元数据

示例：

```json
{
  "id": "project_1_document_2_chunk_5",
  "document": "Spring Boot JWT 登录认证的核心流程……",
  "metadata": {
    "project_id": 1,
    "document_id": 2,
    "file_name": "springboot-jwt.md",
    "chunk_index": 5
  }
}
```

所有查询都必须按照项目过滤：

```python
where={"project_id": project_id}
```

---

### 2.6 MinIO

MinIO 保存用户上传的原始文件：

```text
contentflow/
└── user-{userId}/
    └── project-{projectId}/
        └── document-{documentId}/
            └── 原始文件名.pdf
```

PostgreSQL 的 `cf_document` 保存 MinIO 对象路径，不建议直接保存永久公开 URL。

---

### 2.7 Redis

MVP 中 Redis 只承担简单功能：

* 验证码或登录辅助信息
* 用户信息短期缓存
* 项目信息缓存
* Agent 任务临时状态
* SSE 流式消息临时缓存

第一版不使用 Redis 消息队列，不做复杂分布式任务。

## 3. 核心调用链路

### 3.1 登录流程

```text
Vue提交用户名和密码
    ↓
Spring Security认证
    ↓
查询sys_user
    ↓
校验BCrypt密码
    ↓
生成JWT
    ↓
Vue保存Token
```

---

### 3.2 文档上传与知识库构建

```text
Vue上传文件
    ↓
Spring Boot校验用户和项目归属
    ↓
文件上传MinIO
    ↓
插入cf_document
status = INDEXING
    ↓
Spring Boot调用Agent解析接口
    ↓
Agent读取MinIO文件
    ↓
提取文本
    ↓
文本分块
    ↓
生成Embedding
    ↓
写入Chroma
    ↓
调用Spring Boot内部接口保存切片信息
    ↓
写入cf_document_chunk
    ↓
更新cf_document
status = READY
```

失败时：

```text
status = FAILED
error_message = 失败原因
```

---

### 3.3 AI 内容生成

```text
用户输入创作要求
    ↓
Vue发送消息到Spring Boot
    ↓
Spring Boot校验JWT和项目归属
    ↓
保存USER消息
    ↓
调用LangGraph服务
    ↓
加载项目上下文
    ↓
解析用户要求
    ↓
判断是否需要RAG
    ↓
从Chroma检索Top5片段
    ↓
生成结构化内容
    ↓
通过SSE流式返回Spring Boot
    ↓
Spring Boot转发给Vue
    ↓
保存ASSISTANT消息
```

---

### 3.4 内容保存

```text
用户点击保存
    ↓
Vue提交标题、摘要、正文、标签、引用
    ↓
Spring Boot校验项目归属
    ↓
写入cf_content
    ↓
写入cf_content_tag
    ↓
返回contentId
```

引用资料可以直接保存为：

```sql
references_json JSONB
```

这样第一版不需要新增内容引用关系表。

## 10. 推荐开发边界

第一版保持以下原则：

1. Vue 只能访问 Spring Boot。
2. Agent 不能直接操作 PostgreSQL。
3. Spring Boot 不直接操作 Chroma。
4. Spring Boot 负责权限和业务数据。
5. Agent 负责推理、RAG 和结构化生成。
6. MinIO 只保存原始文件。
7. Chroma 只保存知识片段和向量。
8. PostgreSQL 保存业务记录和向量关联 ID。
9. 所有资源查询必须校验当前用户。
10. 所有 Chroma 检索必须使用 `project_id` 过滤。

这套结构既能展示完整 AI 应用链路，又不会引入微服务、消息队列、多 Agent 等不必要复杂度，适合 Codex 快速生成和本地 Docker Compose 部署。

建议直接把这部分保存为项目根目录的 `docs/architecture.md`，并让 Codex 严格按模块边界逐阶段实现。
